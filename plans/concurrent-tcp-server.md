# 下一个项目：concurrent-tcp-server

状态：建议现在建立一个独立仓库；2026-09-24 检查时可访问仓库列表中尚无该仓库。当前 GitHub 连接提供文件与 Issue 写入，但没有创建仓库工具；本次完成规划，不声称已创建远程仓库。

## 目的与边界

复用 ThreadPool，把语言与并发知识用于实际网络服务；学习 Linux socket、连接生命周期、阻塞与性能测量。

环境目标为 Linux（Windows 可使用 WSL）；先确认本地可用环境。v0 是原始 TCP echo 服务，不实现 HTTP、数据库或业务系统。TCP 是字节流，应处理实际读写长度、部分发送、EOF 和失败路径。

## 接入线程池时的设计问题

- 每个连接由哪个对象/线程最终关闭？如何避免 fd 重复关闭与复用错误？
- recv 阻塞时 stop 如何结束？需要显式连接关闭/超时等策略，并测试。
- 连接数超过 worker 数会怎样？队列和连接资源是否有上限？
- 使用线程池现有接口时遵守单个外部线程 stop 的约定。
- 尽量复用固定版本依赖，记录 commit，不复制一份未注明来源的实现。
