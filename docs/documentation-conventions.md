# 学习文档命名与记录规范

更新日期：2026-10-21。总控与三个项目仓库共用本规范；学习结果、原始日志和旧提交的证据含义不因重命名改变。

## 文件命名

有明确时间截点的学习记录使用：

```text
YYYY-MM-DD-WNN-type.md
```

| type | 中文名称 | 用途 | 示例 |
|---|---|---|---|
| review | 周复盘 | 一整周的计划、实际交付和反思 | 2026-10-17-W06-review.md |
| checkpoint | 阶段记录 | 截至某日的阶段状态，不冒充整周完成 | 2026-10-21-W07-checkpoint.md |
| verification | 归档核验 | 为归档执行的独立检查，说明执行者与验证范围 | 2026-10-19-W07-verification.md |
| experiment | 实验报告 | 后续专项实验的配置、结果与解释 | YYYY-MM-DD-WNN-experiment-topic.md |

同日同类型确有多份报告时，才追加简短英文主题，如 `-thresholds`；否则不额外加后缀。英文主题使用小写、单词间用连字符。正文标题用中文，格式为 `# W07 阶段记录：主题`；跨仓库描述同一阶段时使用相同主标题，仓库职责在正文和索引说明。

日期含义：review 使用覆盖周的结束日；checkpoint 使用状态截至日；verification/experiment 使用实际核验/实验日。补写日期单独写进元信息，不把补写日期冒充发生日期。

## 周次和日期

- W01 从 2026-09-06 开始，每周日到周六，不是 ISO 周编号。
- 文件名、标题、索引和正文统一两位周次：W03、W06、W07；占位符写 WNN。
- 元信息日期使用 YYYY-MM-DD，区间使用 YYYY-MM-DD～YYYY-MM-DD；历史输出中的原始日期不改。
- 每份阶段文档包含：学习周、记录类型、截至日期、记录日期；补写注明“补写”。实际时长未知就写未记录。

## 目录与索引

| 仓库 | 位置 | 职责 |
|---|---|---|
| ai-infra-roadmap | weekly-reviews/ | 跨项目复盘、阶段记录与历史核验；链接子项目详细证据 |
| llm-inference-lab | reports/ | 模型学习记录、归档核验与实验报告 |
| llm-inference-lab | reports/evidence/YYYY-MM-DD/ | 原始输出与 manifest，保留实际命令和源码摘要 |
| 两个 C++ 系统仓库 | docs/ | 专题设计与按日期记录的进度，当前不为少量文档增加新目录 |

两个主记录目录都提供 README.md 索引，按截至日期倒序；同日先学习记录、后核验。仓库首页统一用“最新学习记录”，列最近记录并链接完整索引。同一实验详细日志只保存在对应子仓库，总控只写摘要和链接。

README.md、HOW_TO_USE.md、TEMPLATE.md 保留常规入口命名；now.md、roadmap.md、learning-plan.md、environment.md、design-notes.md 等持续维护的说明文档使用稳定主题名，不强行增加日期。Issue 专题记录保留 issue-8-task-1.md 等关联命名。学习脚本不属于本次文档重命名范围。

## 状态与证据

完成状态分别描述：已学习、运行通过、指导下完成、独立验收通过。不要用同一个“完成”掩盖差异。延期关闭不是实现完成；计划小时数不是实际投入。
历史报告保持当时结果和未完成项；当前待办以总控 now.md、最新阶段记录及 Issue 为准，不让旧快照覆盖新进度。

## 链接与重命名

- 同仓库用相对链接，跨仓库当前入口用 blob/main 链接。
- 固定到具体 commit SHA 的证据链接保留原路径，因为它指向重命名前的历史版本。
- 重命名时同步所有仓库内引用、跨仓库 main 链接、首页/索引/模板及受影响的 Issue。
- 不保留一份旧名全文和一份新名全文，避免双份记录继续漂移；旧版本仍可通过 Git 历史与固定提交链接访问。
- 修改后检查内部路径、锚点、周次/日期和所有待发布文件；纯文档规范化不重跑模型训练来冒充新增学习成果。

## 新建流程

1. 先确定记录类型、截至日期与周次。
2. 复制所在目录的 TEMPLATE.md，填写元信息和真实结果。
3. 将记录加入目录索引，并更新首页“最新学习记录”。
4. 有新的当前任务时更新 now.md 和对应 Issue；保留历史快照。
